# Requests from Module B (legacy import) for files it does not own

None of these block the module; each has a workaround in place.

1. **`src/Domain/Codes/CodeAssigner.php` — accept an explicit `date_assigned => null`.** `insertInternal`/`insertSell` use `$data['date_assigned'] ?? gmdate('Y-m-d')`, so a row from a sheet with no date gets today's date. The importer works around it by setting `date_assigned = NULL` afterwards on the rows it created. Suggested change: `array_key_exists('date_assigned', $data) ? $data['date_assigned'] : gmdate('Y-m-d')`.
2. **`src/Domain/Codes/CodeAssigner.php` — a cheaper path for bulk manual entry.** `manualSell` costs ~2 ms per code (prefix lock, suffix lookup, two existence checks, insert, counter update, a re-select with joins, audit insert — each a separately prepared statement). 8,100 cross-reference rows take ~40 s. Ideas, in order of value: reuse the already-fetched prefix/suffix rows when the caller passes them; build the returned row from the insert data instead of re-selecting; let `Db` cache prepared statements by SQL text (`src/Core/Db.php`). None of this is needed for correctness.
3. **`deploy/` (php-fpm pool / nginx site) and `config.env.example` — upload limits and socket.** The import accepts files up to 25 MB, so the pool needs `upload_max_filesize = 30M`, `post_max_size = 100M`, `max_execution_time = 600` (or the import route needs the nginx `client_max_body_size 100m;` too). Also: when MariaDB is local, setting `DB_SOCKET=/run/mysqld/mysqld.sock` in the generated config halves the import time (TCP → socket); `Db::fromConfig` already supports it.
4. **`src/Http/Controllers/Admin/AdminController.php` — admin home badge.** It would help to show the count of open import issues next to "Import legacy codes" in `areas()`; `ImportIssues::openCount()` gives it. Not done because the file is shared.
5. **`db/migrations/0001_schema.sql` — optional index.** `chroma_import_issues.raw_json` holds a `fingerprint` used to de-duplicate issues across re-runs via `JSON_VALUE(raw_json, '$.fingerprint')`. With a few hundred issues a scan is fine; if the table ever grows large, a `fingerprint CHAR(40)` column with an index (added in a new migration) would be better.
6. **`resources/components/confirm-form.php` — the reason is never posted.** The `reason` text input and its hidden mirror sit inside `<template x-teleport="body">`, so Alpine moves them out of the `<form>` and the browser submits only `_token` (seen in the request log: `POST /admin/import/issues/5/discard  _token=…`). Any screen using `'reason' => true` (void a code, retire a prefix…) will fail its "say why" validation. Fix: keep the hidden `<input name="reason" :value="reason">` outside the teleported template (next to the CSRF field), or submit via fetch. Until then the import module uses a new component, `resources/components/confirm-reason-form.php`, which keeps the reason field inside the form on the page; other modules may want it too.
