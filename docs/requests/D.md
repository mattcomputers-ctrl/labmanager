# Module D requests (changes needed in files this module does not own)

0. **BLOCKING — `src/Http/Controllers/WizardController.php`: every `/wizard/*` URL is a fatal error.** `public function done(Request $request): Response` is incompatible with the base `Controller::done(Request $request, string $redirectTo, array $payload = []): Response` (PHP refuses to load the class: "Declaration of … must be compatible with …", see `/tmp/php-8084.log`), so no Easy-mode wizard from any module can run over HTTP. One-line fix in WizardController: `public function done(Request $request, string $redirectTo = '', array $payload = []): Response` (or rename the action to `finished` and change the route in `routes/00-core.php`). Module D did not touch the file; its wizards were verified with PHPUnit (wizard classes driven directly) and their templates rendered through the View layer for screenshots.

1. **`src/Http/Controllers/Api/LookupApiController.php` — `upperBound()` bugs** (used by `/api/codes/search`, the typeahead that quick assign, link and manual entry rely on):
   - It returns a float (TypeError, HTTP 500) when the typed number has more than ~18 digits or is `PHP_INT_MAX`: `$n + 1` overflows. `storage/logs/app.log` shows these errors from typing long numbers. Suggested fix: clamp the parsed number (`$i['number'] > 999999 → return []`) before calling it, or declare the return type `int|float` and guard.
   - A single open range (`E6374` → `6374 … 637500`) also matches unrelated numbers in between (E6374 pulls in E9102). `CodeSearch::numberRanges()` (module D) builds the correct per-digit BETWEEN ranges; the typeahead could reuse it: `[$cond, $params] = ...` or simply `WHERE number = ? OR (number BETWEEN ? AND ?) …`.
2. **`resources/components/form/lookup.php`** — the typeahead posts only the chosen id, never the chosen label, so a wizard "Back"/review cannot show the text the user picked without a second lookup. Suggest adding `<input type="hidden" name="<name>_label" :value="value ? q : ''">`; `Wizard::validateStep` already stores `<name>_label` when it is posted. Module D resolves labels server-side for now.
3. **`resources/views/layouts/app.php`** — scripts in the `head` section run after `alpine.min.js` (deferred, in order), so a deferred module script cannot register `Alpine.data` components before Alpine starts. Module D loads `codes.js` without `defer` to work around it. A cleaner fix: emit the `head` section before the Alpine script tags, or add a `scripts` section that is rendered before `alpine.min.js`.
4. **`src/Core/Router.php`** — `->permission(a, b)` requires all keys. Several code pages need "either permission" (`codes.assign_sell` OR `codes.assign_internal` for notes/description edits and the quick assign page); module D checks these in the controllers with `Auth::canAny()`. An `->anyPermission(...)` helper on `Route` would move the check back onto the route.
5. **`resources/components/confirm-form.php` — `reason` is never posted.** With `reason => true` the `<input type="hidden" name="reason" :value="reason">` sits inside the `<template x-teleport="body">`, so Alpine moves it out of the `<form>`; the POST body is just `_token` (verified by capturing the request: `/codes/s/647/void` posted `_token=…` only). Fix: move the hidden reason input next to `csrf_field()` outside the template, or build the form inside the dialog. Module D added `resources/components/void-button.php` (form inside the dialog) and uses it for voids (the import module added its own `confirm-reason-form.php` for the same reason); other modules that void with a reason will hit the same bug.
6. **`src/Domain/Codes/CodeAssigner.php::alreadyUsedMessage`** shows the unpadded normalized code (`BN777 is already used…`) while the code is displayed as `BN0777` everywhere else. Suggested: build the message with `CodeFormat::sell($prefix['code'], $parsed['number'], (int) $prefix['min_digits'], $parsed['suffix'])`. Module D's `ManualEntry` pre-checks duplicates with the padded display before calling `manualSell`, so the message is right on `/codes/manual` and the wizard; other callers of `manualSell` (the import, project items) still get the unpadded one.
7. **`src/Domain/Codes/CodeFormat.php` / `CodeAssigner::manual*`** do not bound the parsed number or version: `(int) '99999999999999999999'` saturates at `PHP_INT_MAX`, and `manualSell`/`manualInternal` then fail with a PDO "out of range" / "data too long" exception (HTTP 500) instead of a message. Module D's `ManualEntry` refuses these before calling `CodeAssigner`; a check inside `CodeAssigner` (number ≤ 999999, version ≤ 20 chars) would protect the import and the API too.
8. *(Done in module D, for information)* `resources/views/admin/settings/index.php` and `AppSettings` document `{E}` as the SDS placeholder; `CodeDetails::sdsUrl` now accepts both `{E}` and `{code}`, so nothing is needed there.
