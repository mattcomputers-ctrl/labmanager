# Module D decisions — code lookup, logs, code pages, quick assign, void, link, manual entry

1. **Lookup results are grouped by product.** A product is an E number with every sell number linked to it, or a sell number that has no E number yet. The search is a UNION of indexed probes (exact normalized sell number, `sell_number_normalized LIKE 'Y1000%'`, E number exact + "starts with these digits" ranges, `number = n` for an all-digit query, prefix code, `legacy_internal_code`, FULLTEXT on both description columns, customer ids from the indexed customer name) that yields product keys; the keys are grouped, ranked (exact match first), paginated in SQL, and only then are the page's rows loaded. No `LIKE '%…%'` anywhere.
2. **"Starts with these digits" for E numbers** means E63 → E63, E630–E639, E6300–E6399 … (one BETWEEN range per extra digit), never everything in between. `LookupApiController::upperBound` (not this module's file) uses a single open range, which makes E6374 also match E9102 — see `docs/requests/D.md`.
3. **An all-digit query** (`6374`) searches both E numbers and sell numbers with that number under any prefix; the sell probe scans the `(prefix_id, number)` index, not the table.
4. **A query that is only letters** (`Y`, `uv`) and equals a prefix code lists that prefix, lowest number first (handy for "browse Y"). Browsing a prefix without a term (`/codes?prefix=Y`) does the same.
5. **Multi-word queries** (`T2449 Blister`) try the whole string and the first word as a code, and the whole string as fulltext words; the union of the readings is returned.
6. **Voided codes stay visible** in lookup and logs, greyed with a red "Voided" badge; "Active only" / "Voided only" filters narrow the list. A product card is greyed only when its E number is voided or every one of its sell numbers is.
7. **Logs order:** a prefix log is by number descending (newest number first, suffix variants together); the E log by number then version descending. Both support search within the log, active/voided filters, a date range (Expert), CSV/XLSX export (capped at 20,000 rows) and server-side pagination.
8. **SDS link pattern:** `sds_base_url` + `/` + `E` + base number (`https://sds.example.com/E9102`). Versions share the base E number (`E6374-10` → `…/E6374`). If the base URL contains `{E}` (the placeholder Admin → System documents and validates) or `{code}`, the E number is substituted there instead (`http://sds.precisionink.local/sheet/{E}` → `…/sheet/E9102`), so an SDS system with a query-string lookup works without code changes. The link is only shown when the setting is non-empty.
9. **Notes and description edits** on code pages are allowed to anyone with either assign permission (`codes.assign_sell` or `codes.assign_internal`), and are audited as `code.notes` / `code.description` with before/after snapshots. Unchanged saves write nothing.
10. **The quick-assign operation lives in `src/Domain/Codes/QuickAssign.php`** (a new file beyond the owned list; needed so the wizard, the Expert page and the tests call one operation). It validates the request shape; counters, prefixes, suffixes and reasons are checked by `CodeAssigner`. Everything happens in one `Db::transaction`, so a refused sell number rolls back the E number assigned a moment earlier.
11. **A reason is required when adding a sell number to an existing product** (alias); it is optional for brand-new products. The description defaults from the product; the customer defaults from the product unless another is chosen.
12. **A product that already has an E number cannot get another one** from quick assign — the message tells the user to choose a sell number or pick "brand-new product". A sell number without an E number can get one (and the existing sell number is linked to it, audited as `code.link`).
13. **Permissions for quick assign:** the page/wizard opens with either assign permission; the operation refuses (403) if the chosen kind of code needs a permission the user lacks. The forms only offer the kinds the user may assign.
14. **Typeahead reuse:** linking and manual entry accept either an E number or any sell number of the product from `/api/codes/search`; a sell number resolves to its E number. A sell number with no E number is refused with a plain message.
15. **Easy ↔ Expert carry-over:** the wizards' "Expert" switch builds `/assign?…` or `/codes/manual?…` URLs with the entered values; the Expert pages pre-fill from the query string. The Expert pages redirect Easy-mode users to the wizard unless `?expert=1` is present (used by those links).
16. **Exports are audited** (`code.export`, with the query/log and row count) so it is visible when the cross-reference was downloaded.
17. **Retired prefixes** show in the logs index under their own heading and in the lookup's prefix filter, but not in the "browse a prefix" chips or assign forms.
18. **The "already linked" case** on the Expert link form is a no-op with an info toast rather than an audit entry.
19. **Manual entry has its own small operation, `src/Domain/Codes/ManualEntry.php`** (a second file beyond the owned list, for the same reason as #10: one operation for the Expert page and the wizard). Before calling `CodeAssigner::manualSell/manualInternal` it refuses, in plain words, what the database could not store — sell numbers over 6 digits, E numbers over 6 digits, versions over 20 characters (`CodeFormat` saturates long digit strings at `PHP_INT_MAX`, which used to surface as an HTTP 500 "out of range" PDO error) — and a code that is already used, naming it the way it is displayed everywhere else (`BN0777 is already used by E6374`, not `BN777`). The wizard runs the same checks on the code step so the user hears about it before the details step.
20. **Reason "Other" always comes with a "Say why" box.** Both manual-entry shells show `reason_text` when the reason is Other (Expert: Alpine `x-show`; Easy: the generic `codes/wizard-details` step template, which supports a `show_when` key on a field spec) and require it only then, matching quick assign.
21. **The void wizard says up front when a code is already voided** (one informational screen with a way back, no reason asked, no commit possible) instead of asking for a reason and refusing on the review screen. The detail pages hide the Void button; the URL is still reachable from history or bookmarks.
22. **Source is shown in plain words everywhere** (`CodeSearch::sourceLabel`: "Assigned in Chroma", "Imported from the spreadsheets", "Entered by hand") — lists, pages and exports alike; the raw `assigned`/`import`/`manual` values never reach the screen.
23. **`db/migrations/0040_sell_number_index.sql` adds `ix_sell_number (number)`** so the all-digit lookup probe (`6374` → Y6374, BK6374 …) hits an index; every key on `chroma_sell_numbers` started with `prefix_id`, so that probe scanned the table (EXPLAIN type=ALL). Verified with EXPLAIN (`ref`, `ix_sell_number`, `Using index`) and a test.
24. **Both shells collect the same fields:** the quick-assign wizard now has Notes (like `/assign`), the manual-entry wizard collects the vendor's code (like `/codes/manual`), and the Expert pages pre-fill all of them from the wizard's "Expert" switch.
25. **The E-number page at phone width** uses `minmax(0, 1fr)` columns and `min-width: 0` on the stacks/cards so the sell-numbers table scrolls inside its own `.table-wrap` instead of pushing the page past the viewport.
26. **The Expert manual-entry form keeps what was typed after a server-side refusal** (`old()` wins over the query-string defaults). Before, a refusal such as "say why" or "already used" reloaded the form with the code and description blank. Found while verifying #20.
