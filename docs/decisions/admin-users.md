# Decisions — module E1 (Admin: users & groups, lists, project types, customers)

1. **Customer admin operations live in `src/Domain/Lists/ListAdmin.php`** (add, rename, activate, merge) rather than a new
   `CustomerAdmin` class, because the module's file ownership does not include a customers domain file and
   `Domain/Customers/Customers.php` (lookup / find-or-create shared with import and CMS sync) must not change. The spec treats
   customers as one of the admin "lists" under the `admin.lists` permission, so the grouping is defensible. Easy to split later.
2. **Only an Administrator can promote someone to Administrators.** The spec only forbids *removing* / *deactivating* an
   administrator by a non-administrator; without the symmetric rule anyone with `admin.users` could add themselves to
   Administrators and then do both. `UserAdmin::assertMayChangeAdminMembership` enforces both directions.
3. **Administrators always hold every permission.** The seeder re-adds all keys on every run anyway, so the permission form for
   that group is shown read-only and `GroupAdmin::setPermissions` refuses changes with an explanation. Name is fixed too
   (`Auth::isAdmin()` checks the name); description and membership can be edited.
4. **Temporary passwords are "Word-Word-Word-NN"** (e.g. `Amber-Harbor-Pilot-42`), generated by `UserAdmin::generatePassword()`.
   Readable over the phone and typeable on the lab PC; always passes `Auth::passwordProblem`. Shown exactly once: on the wizard
   success screen, or on the user page right after create/reset (held in the session under `_shown_password` and pulled on first view).
5. **Resetting a password or deactivating signs the user out everywhere** by deleting their rows in `chroma_sessions`
   (a reset keeps the current session when an admin resets their own).
6. **Usernames are stored lowercase and never change** (the logs identify people by them); display name, email and initials can change.
7. **Simple list entries (ink series, coatings, substrates) can be hard-deleted only when nothing references them**
   (`chroma_project_items.*_id` and `chroma_projects.default_*_id`); otherwise `ListAdmin::delete` refuses with a message that
   points to Deactivate. The UI only shows Delete when the usage count is 0.
8. **Customer merge moves `chroma_projects.customer_id`, `chroma_internal_codes.original_customer_id` and
   `chroma_sell_numbers.original_customer_id`**, deactivates the duplicate (never deletes it), appends a "Merged into …" line to
   its notes, and writes two audit rows (on the kept and the merged-away customer). If the duplicate carried a CMS id and the kept
   customer has none, the CMS id moves to the kept customer (and its source becomes `cms`) so the sync keeps matching the right
   row instead of re-creating the duplicate. The kept customer must be active.
9. **Stages and item statuses get a slug code from their label** (`uniqueCode()`, suffixed `_2`, `_3` … on clashes within the
   type) so the lab never has to type codes. Reordering renumbers the whole scope 10, 20, 30 … so orders stay unambiguous.
10. **A status marked "not finished" cannot be a "success"** (`is_success` is cleared), and at least one active not-finished status
    must remain in each list so new items have a starting status. Stages / statuses in use can be deactivated but not removed.
11. **"Customize for this type" copies the shared status list** into type-specific rows; "Use the shared list again" deletes
    them, but only while no item carries one of them. The shared list itself is edited at `/admin/item-statuses`.
12. **A project type can be deactivated unless it is the only active one**; its code never changes after creation.
13. **One schema addition: `db/migrations/0050_customers_fulltext.sql`** adds a FULLTEXT index on `chroma_customers.name_normalized`
    (idempotent `CREATE FULLTEXT INDEX IF NOT EXISTS`). Everything else uses `db/migrations/0001_schema.sql` as is.
14. **Easy vs Expert in lists**: Easy mode shows fewer columns (no last sign-in / password flag / notes / sort) and 25 rows per page;
    Expert shows everything and 50 rows. Behaviour is identical.
15. **Customer search never uses an infix LIKE.** `ListAdmin::customers()` joins a derived table made of three indexed lookups
    (`name_normalized LIKE 'q%'`, `cms_customer_id = q`, and `MATCH (name_normalized) AGAINST ('+w1* +w2*' IN BOOLEAN MODE)`),
    so "labels" still finds "ACME Labels, Inc." as the CMS list grows. Words shorter than 3 characters are not in the FULLTEXT
    index (`innodb_ft_min_token_size`), so they are left out of the MATCH; a search made only of short words is a prefix match.
    The derived-table form was chosen because an OR across a FULLTEXT and a B-tree index makes MariaDB scan the whole table.
16. **You cannot remove yourself from the Administrators group** (`UserAdmin::assertMayChangeAdminMembership`), mirroring "you
    cannot deactivate yourself": an Administrator who removed themselves would lose every admin screen on the next request with
    no way back. Another Administrator can still remove them. The last-admin rule is checked first, so its message wins when both apply.
17. **A refused inline save reopens the same row.** The list, stage and status editors redirect back with `?edit={id}` (or
    `edit_stage=` / `edit_status=`), the typed values in the row's inputs and the message under them, instead of landing in the
    "Add" box at the top of the page.
18. **Phone layout for the list editors**: tables marked `table-stack` (lists, stages, item statuses) render each row as a small
    card below 640px with the column name in front of each value, so the status and the Edit/Deactivate buttons are never hidden
    behind a horizontal scroll. Desktop and tablet layouts are unchanged.
19. **The Admin landing page needs an admin permission** (`anyPermission(Permissions::adminKeys())`), so a Lab, Sales or Read-only user who types `/admin` gets the standard "You can't open this" page instead of an empty tile grid.
20. **A generated temporary password never breaks inside a word** on a phone: the big code display breaks only at hyphens (or anywhere as a last resort for a code that cannot fit at all) and uses 22px mono below 480px so `Word-Word-Word-NN` fits on one line. The sign-in address on that screen comes from `APP_URL` in the config, which the installer sets to the server's address.
